# Capacitor によるアプリ化に向けて

現段階では Capacitor の導入は行いません。将来の移行を妨げないための前提と課題をまとめます。

## 現在の構成で備えていること

`www/` を Capacitor の既定の `webDir` と同じ名前にしているため、導入時は `capacitor.config.json` で `"webDir": "www"` を指定するだけで済みます。ビルド工程がないので、Web とアプリで同じファイルをそのまま使えます。

リソースはすべて相対パスで、外部URLへの依存もありません。viewport に `viewport-fit=cover` を指定し、CSS で `safe-area-inset` を考慮しているため、ノッチ付き端末にも対応しやすくなっています。入力は Pointer Events で統一し、`touch-action: none` でスクロールやズームによる誤動作を抑えています。

## 導入時の課題

| 項目 | 内容 |
| --- | --- |
| 音声の遅延 | リズムゲームでは最重要。Android の WebView は Web Audio の出力遅延が端末ごとに大きく異なるため、判定タイミング補正（オフセット調整）設定を必ず用意する。不足する場合はネイティブ音声プラグインを検討 |
| 時刻の基準 | 判定は `AudioContext.currentTime` を基準にし、`Date.now()` やフレーム数に依存しない |
| 音声の自動再生 | WebView でもユーザー操作起点でないと再生できない。現在のスタート画面のタップでアンロックする方式を維持する |
| バックグラウンド | `visibilitychange` で一時停止する処理を入れてある。Capacitor 導入後は `@capacitor/app` の `appStateChange` と Android の戻るボタン処理も追加する |
| データ保存 | `localStorage` は WebView でも使えるが、OS により消去される可能性がある。保存処理は1つのモジュールに集約し、後から `@capacitor/preferences` に差し替えられるようにする |
| 画面の向き | 縦横どちらで遊ぶかを早めに決め、ネイティブ側で固定する |
| 画面スリープ | プレイ中に画面が消えないよう、将来 Keep Awake 系のプラグインが必要になる可能性がある |
| 端末性能 | Canvas 描画の負荷を抑え、低価格帯の Android でも60fpsを目標に検証する |

## 避けるべき実装

ブラウザ専用の機能（`window.open` による別タブ遷移、ページ遷移を前提にした画面構成、Cookie 依存の処理）は WebView で挙動が変わるため使わないようにします。画面遷移は単一ページ内で切り替えます。
