# オフライン対応に向けて

オフライン動作は将来の必須要件です。現段階では実装せず、課題を整理します。

## 現状

ゲーム本体は未実装です。現在の土台は外部URLを一切参照しておらず、`npm test` で外部参照を検出するため、オフライン化を妨げる要素はありません。

## アプリ版（Capacitor）

Capacitor は `www/` の中身をアプリに同梱するため、同梱ファイルだけで動く限り自動的にオフラインで動作します。注意すべきは、外部CDN・Webフォント・オンラインの楽曲や譜面配信・広告・ランキングなどのネットワーク機能です。これらは「通信できないときも遊べる」設計にする必要があります。

## Web版（GitHub Pages）

ブラウザでオフライン動作させるには Service Worker と Web App Manifest が必要です。

| 課題 | 方針 |
| --- | --- |
| キャッシュ対象の管理 | ファイル一覧を手書きすると更新漏れが起きる。ファイル一覧を生成するスクリプトを `tools/` に用意する |
| 更新の反映 | キャッシュ名にバージョンを含め、更新時に古いキャッシュを削除する。古い版のまま遊ばれ続ける問題に注意 |
| サブパス | 登録は `navigator.serviceWorker.register('sw.js')` と相対で行い、スコープを `/ClaudeGame005/` に収める |
| 音源の容量 | 楽曲ファイルは大きく、ブラウザのキャッシュ容量制限に触れうる。圧縮形式（AAC/Opus）とビットレートを早めに決める |
| 音源形式の互換性 | iOS Safari は Ogg Vorbis 非対応の版がある。AAC（m4a）か MP3 を基本にする |
| Capacitor との関係 | アプリ版では Service Worker は不要で、二重キャッシュや更新トラブルの原因になる。アプリ内では登録しないよう判定を入れる |

## データ保存

スコアや設定は端末内に保存し、通信がなくても失われないようにします。保存処理は1つのモジュールに集約し、Web では `localStorage`、アプリでは `@capacitor/preferences` に差し替えられる形にします。保存データにはバージョン番号を含め、将来の形式変更に備えます。
